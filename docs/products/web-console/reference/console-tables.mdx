The console keeps its own state in ordinary tables of one database, named by the `admin_database` setting (default
`console_admin`; see [Configuration](/products/web-console/reference/configuration#web-console)). The tables are created
only when an administrator selects **Set up** on a page, with `CREATE DATABASE IF NOT EXISTS` and
`CREATE TABLE IF NOT EXISTS`, so running a setup again is safe. The DDL below is the one in `programs/server/console.html`
(`ADMIN_TABLES`, `DAP_TABLES`, `BACKUP_TABLES`, `CLUSTER_TABLES`, `IDP_TABLES`).

The tables are stored on the server the console is connected to and are not replicated. To remove the console's data,
drop the database; the console then works as if it was never set up.

## Versioning model {#versioning-model}

The tables follow two patterns:

| Pattern | Engine | How a change is written | How it is read |
|---|---|---|---|
| Current state | `ReplacingMergeTree(updated_at)` with the key of the object in `ORDER BY` | A new row with the whole object replaces the previous version. Removing the object inserts a row with `deleted = true`. | `FINAL ... WHERE NOT deleted` |
| History | `MergeTree` | Rows are appended and never updated. | The latest row, or all of them |

The writer and the time of each row are columns the server fills in:

- `updated_by`, `created_by`, `requested_by`, `recorded_by`, `ran_by`, and `actor` are `MATERIALIZED currentUser()`;
- `updated_at`, `created_at`, `requested_at`, `at`, `ran_at`, and `event_time` are `MATERIALIZED now64(3)`;
- `server_host` of `audit_log` is `MATERIALIZED hostName()`.

Each such writer column has a `CHECK` constraint (for example `CONSTRAINT updated_by_is_writer CHECK updated_by = currentUser()`)
that rejects any other value, also when `insert_allow_materialized_columns` is enabled. A user who can insert into a
table therefore cannot write rows in another user's name. The tables are ordinary tables, though: users with `ALTER`,
`TRUNCATE`, or `DROP` on them can change or remove rows, so they are not tamper-proof. Grant `SELECT` and `INSERT` only,
and keep `ALTER` and `DROP` to the server administrators.

All times are `DateTime64(3, 'UTC')` unless noted. Columns that hold JSON are `String`.

## Reader role {#reader-role}

The **Set up** of **Component Access** also creates the role `<admin_database>_reader` (by default
`console_admin_reader`) with `SELECT` on `component_policy`, and offers to grant it to the users and roles created with
SQL. Users who cannot read the policy do not see the components it governs, so every console user needs this role among
their default roles (or `SELECT` on the table). A role is used because granting it needs only the admin option on the
role, while granting `SELECT` on the table directly would need it `WITH GRANT OPTION`.

## Administration tables {#administration-tables}

Created by **Set up** on **Component Access**, which also inserts one rule per governed component for all users
(`open` true; `view_data` and `run_queries` true for panels; `administer` false), and a `setup` record in the audit log.
The retention of the audit log is chosen in the dialog: 1 to 36500 days, default 365.

### `audit_log` {#audit-log}

```sql
CREATE TABLE console_admin.audit_log
(
    event_time DateTime64(3, 'UTC') MATERIALIZED now64(3),
    actor String MATERIALIZED currentUser(),
    server_host LowCardinality(String) MATERIALIZED hostName(),
    correlation_id UUID,
    scope String,
    target_type LowCardinality(String),
    target_name String,
    action LowCardinality(String),
    summary String,
    result Enum8('success' = 1, 'failure' = 2, 'partial' = 3),
    error String,
    details String,
    CONSTRAINT actor_is_writer CHECK actor = currentUser(),
    CONSTRAINT host_is_server CHECK server_host = hostName()
)
ENGINE = MergeTree ORDER BY event_time
TTL toDateTime(event_time) + INTERVAL 365 DAY
```

| Column | Type | Meaning |
|---|---|---|
| `event_time` | `DateTime64(3, 'UTC')` | When the record was written. Filled in by the server. |
| `actor` | `String` | The user who wrote the record. Filled in by the server. |
| `server_host` | `LowCardinality(String)` | Host name of the server that stored the record. Filled in by the server. |
| `correlation_id` | `UUID` | ID of the change. The console also sets it as the `log_comment` of the statements of the change; for backup and cluster operations, it is the operation ID. |
| `scope` | `String` | `local`, or `cluster:<name>` for a change applied `ON CLUSTER`. |
| `target_type` | `LowCardinality(String)` | Kind of object changed, for example `user`, `role`, `platform`, `backup`, or `data_access`. |
| `target_name` | `String` | Name of the object changed. |
| `action` | `LowCardinality(String)` | What was done, for example `setup`, `delete_role`, `dap_reconcile`, `server_bundle`, `recovery_rehearsal`, or `sso_create_user`. |
| `summary` | `String` | One-line description. |
| `result` | `Enum8` | `success`, `failure`, or `partial` (a change that took effect on some servers or steps only). |
| `error` | `String` | Sanitized error message: passwords and keys are masked. |
| `details` | `String` | JSON with the steps and their outcome on each server, and other details of the action. |

To change the retention later: `ALTER TABLE console_admin.audit_log MODIFY TTL toDateTime(event_time) + INTERVAL <days> DAY`.

### `component_policy` {#component-policy}

```sql
CREATE TABLE console_admin.component_policy
(
    subject_type Enum8('all' = 1, 'role' = 2, 'user' = 3),
    subject String,
    component LowCardinality(String),
    open Bool,
    view_data Bool,
    run_queries Bool,
    administer Bool,
    deleted Bool DEFAULT false,
    updated_at DateTime64(3, 'UTC') MATERIALIZED now64(3),
    updated_by String MATERIALIZED currentUser(),
    CONSTRAINT updated_by_is_writer CHECK updated_by = currentUser()
)
ENGINE = ReplacingMergeTree(updated_at) ORDER BY (subject_type, subject, component)
```

| Column | Type | Meaning |
|---|---|---|
| `subject_type` | `Enum8` | `all` (every user), `role`, or `user`. |
| `subject` | `String` | Role or user name; empty for `all`. |
| `component` | `LowCardinality(String)` | A [component ID](/products/web-console/reference/http-endpoints#component-ids). |
| `open` | `Bool` | The subject may open the component. The only capability the console enforces. |
| `view_data` | `Bool` | Capability **View data**: compared with the native privileges that govern it. |
| `run_queries` | `Bool` | Capability **Run queries**. |
| `administer` | `Bool` | Capability **Administer**. |
| `deleted` | `Bool` | The rule is removed. |
| `updated_at`, `updated_by` | | Time and writer of the version. |

A capability is allowed when any rule for all users, for the signed-in user, or for one of the roles enabled in the
session allows it. A component without any row is not governed and stays open to everyone.

| `updated_at`, `updated_by` | | Time and writer of the version. |

### Server bundle tables {#server-bundle-tables}

The backup worker stores each server bundle in a temporary table `server_bundle_<id>`, where `<id>` is the first 16
hexadecimal characters of the operation ID, with the columns `part UInt32`, `kind Enum8('header' = 1, 'data' = 2, 'tag' = 3)`,
and `data String`. It backs the table up with `BACKUP TABLE`, and drops it. A bundle restore brings it back as
`server_bundle_restore_<id>` and drops it after use. The tables hold only ciphertext.
